# v3.13 — Forkable owner identity

Internal refactor — no user-visible behavior change on this prod deployment. The owner email + display name moved out of source and into env vars so a fork doesn't ship "scott.t.weaver@gmail.com" baked into every user's JS bundle.

## What's new

Nothing visible to existing users (the Pending / Denied screens still say "Scott needs to approve you" and surface the same mailto link — the values just come from env vars now). The change matters for anyone else cloning this repo as a starting template for their own family-trip dashboard.

## Under the hood

- **`OWNER_EMAIL` and `OWNER_NAME` in `src/lib/supabase.ts` are now env-driven** (`VITE_OWNER_EMAIL`, `VITE_OWNER_NAME`). Both fall back gracefully — empty email suppresses the mailto link; missing name is derived from the email local-part (`scott.t.weaver@…` → "Scott"), falling back to "the admin".
- **`PendingScreen` and `DeniedScreen`** updated to use the new `OWNER_NAME` constant instead of hardcoding "Scott", and to guard the mailto rendering when `OWNER_EMAIL` is empty.
- **Test fixture** in `format.test.ts` switched from `scott.t.weaver@gmail.com` to `test.user@example.com` — pure rename, same semantics.
- **README + CLAUDE.md** updated to document the new env vars, the still-hardcoded SQL trigger (which forkers must edit by hand for now), and refreshed the migration list (now 0001–0010) and the test count (85+).
- Vercel prod env needs `VITE_OWNER_EMAIL` and `VITE_OWNER_NAME` added — until that happens, this deployment renders with the fallback copy ("the admin"). One-time dashboard step.

## Known gap (follow-up)

The `handle_new_user` SQL trigger in `supabase/migrations/0001_init.sql` still hardcodes the auto-admin email. A future patch will introduce an `app_config(owner_email)` table the trigger reads from, so forkers can set it via a one-line SQL UPDATE post-deploy instead of editing the migration file before `db push`. Not blocking — Scott's prod has the right email already; forkers see clear README guidance on the edit they need to make.
