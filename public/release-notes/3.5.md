# v3.5 — Meal ingredients + collapsible meals

Phase 2 of cook-at-the-condo support.

## What's new

- **Ingredients per meal** — each meal now has an Ingredients section. Tap the meal to expand, then tap "Ingredients" to add items. Each row has a quantity (free-text, like "2 lbs" or "a bunch") and the ingredient name. The head chef and any sous chefs can add and remove ingredients; everyone else can see the list.
- **Fast keyboard flow for adding ingredients** — type a quantity, hit Enter, type the name, hit Enter to save. Focus jumps back to the quantity field so you can rattle off a list without touching the mouse.
- **Collapsible meals** — meals start collapsed showing only a one-line summary: meal type, what's being cooked, head chef. Tap to expand for notes, sous chef signups, and the ingredients section. Per-user state, so collapsing meals you've already memorized doesn't affect others.

Phase 3 (shopping list — auto-generated from ingredients or manually added) is queued for a future release.

## Under the hood

- Migration `0008_meal_ingredients.sql` adds the `meal_ingredients` table with a `can_edit_meal_ingredients()` SQL helper that resolves to true when the current user is the head chef, a signed-up sous chef, or admin. All INSERT/UPDATE/DELETE policies route through that helper so the write rules stay aligned with the meal's chef roster as it changes.
- `useMeals` extended to load + sync + cache ingredients alongside meals and sous chefs. Same realtime channel handles all three tables.
- New queue ops `meal_ingredients/insert` + `meal_ingredients/delete` so adds and removes are offline-tolerant like every other mutation.
- Per-meal collapse state reuses the existing `useCollapsedState` hook (the one that already powers the dashboard section cards), so the persistence model is identical: localStorage, per-user-per-device.
- `AddIngredientForm` uses two refs (quantity + name) to script the Enter-key navigation: Enter in quantity advances to name; Enter in name submits and returns focus to quantity. `e.preventDefault()` on both blocks any latent form-submit behavior.
