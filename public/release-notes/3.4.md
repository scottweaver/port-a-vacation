# v3.4 — Meal plan

Phase 1 of cook-at-the-condo support. Plan who's cooking what on which day, and rally helpers in the kitchen.

## What's new

- **Meal Plan card** on the Trip tab (between the Pirate Ship Cruise booking and the Beach Essentials checklist). Shows the trip's meals grouped by day, with the head chef and any sous chefs.
- **Plan a meal** — tap the button to add one. Pick a day (May 25–29), a meal slot (🥞 Breakfast / 🌮 Lunch / 🍝 Dinner / 🍿 Other), give it a title ("Shrimp pasta," "Pancake morning"), optional notes, and the head chef. You can plan a meal that someone else is leading — it doesn't have to be you.
- **I'll help** — anyone can sign themselves up as a sous chef on any meal. Tap again to back out. Head chef and admin can also remove a sous chef (tap their name pill).
- **Edit / delete** — the head chef of a meal (or any admin) sees a pencil icon on the meal card. Delete uses two-tap confirm.

Phase 2 (per-meal ingredient lists) and Phase 3 (shopping list) are queued for next releases.

## Under the hood

- Migration `0007_meals.sql` adds `meals` and `meal_sous_chefs` tables. Both are trip-level (NOT family-private like `packing_status` / `hidden_items`) — all approved users read all meals; head chef + admin write the meal row; self-INSERT/DELETE on sous chef opt-ins.
- New `useMeals` hook follows the established pattern: cache hydration, realtime channel covering both tables, offline-queue-routed writes, sort by date then meal_type (breakfast < lunch < dinner < other).
- `meal_sous_chefs` has a self-DELETE policy + a head-chef-can-remove-anyone policy so users can leave themselves OR be bumped by the meal lead.
- Two-step "tap to confirm" on meal deletion matches the existing delete-checklist-item pattern. ESC closes the modal.
