# v3.1 — Chat polish & update notifications

Quality-of-life follow-up to v3.0's conversation threads.

## What's new

- **Typing indicator** — when someone else is typing in a chat thread you've opened, their name shows up under the input. Works across devices in real time.
- **Browser notifications** — when the app is in the background and a new message arrives, your browser pings you with the sender's name and the start of the message. Tap the notification to come back to the app. (Heads-up: iOS Safari needs the site added to your home screen as an app for notifications to work; other browsers work out of the box.)
- **Update banner** — when a new version of the app is deployed, a red bar appears below the header letting you know to refresh. Tap it to load the new version, no manual reload required.
- **Version in the header** — the small "v3.1 (abc1234)" under "Port A 2026 🏖️" tells you exactly which version is loaded. Handy when reporting a bug.
- **Links in messages** — paste a URL in a chat message and it renders as a tappable link.
- **What's new** — the link you just tapped. Each future update will have its own notes.

## Under the hood

- Version banner uses a `/version.json` file written at build time. The app polls it (3 min in prod, 4 seconds in dev) and broadcasts on a Supabase Realtime channel so the first client to detect an update cascades to everyone connected within ~100ms.
- Typing indicator runs over Supabase Realtime broadcast — no database writes, no persistence. Throttled to one event per second per user; stale typers prune after 4 seconds.
- Release notes (this file) live in the repo at `public/release-notes/3.1.md` and are used both for the in-app modal and the GitHub release body — single source of truth.
