# v3.9 — Condo info 🔑

The condo portal card now shows door code, pool code, wifi, host contact, check-in/out times, and bike + golf cart rental info inline — no more tap-through to the portal for the everyday stuff. Admin can edit any field at runtime from the Admin tab.

## What's new

- **Inline codes + info** on the Condo card: 🔒 door code and 🏊 pool code as big tiles at the top, then wifi, host (with tap-to-call phone), check-in / check-out times, bike rental + golf cart rental (with tap-to-call + tap-to-map), and a free-form notes block.
- **Bike rental** and **golf cart rental** seeded with the two we already use: **Big Shell Bikes** (403 N. Alister, 361-445-7001) and **Joy Carts** (307 Sea Isle Dr, 361-749-2278).
- **Admin → Condo info editor** lets the admin update any of those fields from inside the app. Changes broadcast instantly to every family member's device via realtime — no refresh, no redeploy, no env-var fiddling.
- **Empty fields hide themselves** — if you haven't filled in wifi yet, the wifi row just doesn't render. The card grows as you add info.

## Under the hood

- Migration `0009_condo_info.sql` adds a single-row `condo_info` table (PK enforced as `id = 1`). Approved users read; admin writes (RLS); realtime publication so saves propagate.
- New `useCondoInfo` hook follows the standard cache→realtime→queue pattern. Writes are optimistic locally + queued for offline tolerance.
- `CondoPortalCard` rewritten to render structured info above the existing "Open guest portal" button. Built-in `CartIcon` SVG (Lucide doesn't ship one) keeps the icon set consistent.
- `AdminPanel` gets a new `CondoInfoEditor` section: text fields for every column, dirty-diff Save button, "Last edit Xm ago" stamp. Realtime updates only overwrite the form if the user has no unsaved local changes (single-admin friendly).
- The TrackHS auto-login link still lives in `VITE_CONDO_PORTAL_URL` (Vercel env + local `.env.local`) — kept out of the DB by request, may move later.
